## 1. Цель и критерии успеха

Route Builder — приложение диспетчера курьерского депо из двух экранов. На первом диспетчер выбирает остановки из адресной книги и задаёт число посылок. На втором пишет инструкцию водителю для каждой остановки и отправляет маршрут. Работают стоя, одной рукой, в спешке.

Успех:

1. Ядро из `TASK.md` работает на физическом iPhone против `server.js`, который запущен на Mac в той же сети.
2. Приложение переживает реальное поведение сервиса: не падает, не показывает дубли, не теряет данные. Где `API.md` и сервис расходятся, правильным считается поведение сервиса. При этом клиент **не завязывается на конкретную реализацию мока**: `server.js` — копия staging, и баги там могут проявляться иначе. Правила обработки общие.
3. Двойной тап не создаёт два маршрута. Если после таймаута неизвестно, создан ли маршрут, пользователь об этом узнаёт.
4. Визуально близко к макету.
5. Сеть, DTO и доменная логика вместе с состоянием экранов покрыты юнит-тестами, которые запускаются через `swift test`.
6. Кодовая база такова, что в неё естественно добавить третий экран.

Платформа: iOS 16.0+, Swift, SwiftUI, без сторонних зависимостей. Только iPhone, только портретная ориентация. Интерфейс на английском, LTR.

Запрещено использовать API новее iOS 16: `@Observable`, `ContentUnavailableView`, `scrollTransition`, `scrollTargetBehavior`, `presentationCompactAdaptation` (появился в 16.4) и т. п. Компилятор проверяет это сам, потому что deployment target равен 16.0.

Коммиты и push делает только автор. Агент их не выполняет.

## 2. Объём

### Ядро

**Stops**
- загрузка всего каталога;
- секции по первой букве;
- строка: инициалы, имя, адрес, телефон;
- поиск через API (`q`) и состояние «ничего не найдено»;
- режимы One stop и Multi-stop route;
- пилюля `N×` с окном выбора количества (−, число, +, Save);
- чипы выбранных остановок и кнопка `Continue (N stops)`;
- алфавитный индекс A–Z.

**Instructions**
- карточка на каждую остановку: имя, `N×`, адрес, поле инструкции со счётчиком, Clear all;
- ошибка пустой инструкции на самой карточке;
- кнопка «Remove from route»;
- фокус-эффект ленты (масштаб и прозрачность, без blur).

**Отправка**
- `POST /v1/routes`;
- состояния «отправляем», «ошибка», «успех»;
- защита от двойного тапа;
- экран Success с кнопкой New route.

**Устойчивость** — раздел 3.

### Задачи в конце плана, которые можно отрезать без последствий для ядра

Идут строго в этом порядке:

1. **Полировка окна количества:** поднятая над затемнением строка и стрелка-указатель, как в макете.
2. **Свайп-удаление** карточки вправо, как в макете. Критерий на устройстве: свайп не мешает вертикальному скроллу. Лимит времени — **1 час**. Если не уложились, свайп вырезаем и пишем в DECISIONS.
3. **Notify:** `POST /v1/routes/{id}/notify` (раздел 9.4).
4. **Фото с прошлой доставки:** `GET /v1/stops/{id}/photos` (раздел 8.6).

### Вырезано (записывается в DECISIONS)

- Сохранение черновиков на диск. Черновик живёт только в памяти, но переживает навигацию назад.
- Undo удаления. Вместо него — подтверждение для карточек с непустой инструкцией.
- Ручной ввод адреса: `POST /v1/routes` принимает только `stop_id`, поля для адреса нет.
- Снимок камерой. Строка «Photo of the drop-off point» убрана из карточки.
- Компактная шапка пикера при скролле (экран 4 макета). Шапка фиксированная.
- Blur в фокус-эффекте.
- Тёмная тема: макет только светлый, ставим `.preferredColorScheme(.light)`.
- Встроенные шрифты Heebo и IBM Plex Mono. Используем системные SF Pro и SF Mono с размерами и начертаниями из макета.
- Dynamic Type: размеры шрифтов фиксированные, как в макете.

## 3. Поведение сервиса и как клиент его обрабатывает

Пункты помеченные «[проверено]», подтверждены живыми запросами к `server.js`.

| # | Поведение сервиса | Обработка в клиенте |
|---|---|---|
| S1 | Пагинация может сдвигать страницы: последний элемент предыдущей страницы повторяется, а один элемент теряется. [проверено: при `page_size=10` повторяется `stp_1009`, `stp_1019` не приходит] | Общее правило (§5.5): `page_size=50`, обход страниц, дедупликация по `id`, остановка на пустой или неполной странице либо на странице без новых `id`, жёсткий лимит страниц. Потерянную на сервере запись клиент восстановить не может, это пишем в DECISIONS. |
| S2 | `has_more` недостоверен: на последней неполной странице он `true`. [проверено: `page=2&page_size=50` → `items: []`, `has_more: true`] | `has_more` не декодируем и не используем. |
| S3 | `total` больше реального на 1 (soft-deleted), `total_pages` считается через `floor` и бывает 0. | Не декодируем и не используем. |
| S4 | Периодические 500 и 503 (у 503 есть `Retry-After`), а также задержки около 1,2 с. | Автоповтор только для GET (§5.4). Ошибку показываем как ошибку с Retry, никогда как «ничего не найдено». |
| S5 | Поиск чувствителен к регистру. [проверено: `q=sov` → `null`, `q=Sov` → найдено] | `q` уходит в API как набран. Если ответ успешный, но пустой, дополняем результат локальным поиском без учёта регистра по загруженному каталогу (§7.4). |
| S6 | Пустой результат поиска приходит как `items: null`, пустой просмотр — как `[]`. | `null` → `[]`. |
| S7 | Ответы поиска могут прийти не по порядку запросов из-за задержек. | Debounce, отмена предыдущего запроса, ответ применяется только для текущего `q`. |
| S8 | `+` в query на сервере читается как пробел, а `URLComponents` его не кодирует. [проверено] | Кодируем `+` вручную как `%2B`. |
| S9 | `packages_max` бывает `number`, числовой строкой или `null`. [проверено] | `FlexibleInt?`. Значения ≤0 и мусор → `nil`, то есть лимита нет. |
| S10 | `last_delivery_at` бывает ISO с `Z`, ISO без `Z` и epoch в секундах. [проверено] | `FlexibleDate?`. ISO без `Z` считаем UTC. Нераспознанное значение → `nil`, запись не отбрасываем. |
| S11 | `notes` встречается только как `null` или отсутствует. `zone` есть всегда. | Оба поля `String?`, в UI не используются. |
| S12 | Телефоны в разных форматах. Имена длинные, с эмодзи, начинаются с цифры, содержат `&` и `'`. | Телефон показываем как пришёл. Многоточие везде. Секция `#`. Правило инициалов — §6.2. |
| S13 | Битая запись не должна ронять всю страницу. | Поэлементное декодирование (`LossyArray`), число пропущенных записей возвращается наружу. |
| S14 | `POST /v1/routes` молча обрезает `instructions` до 200 UTF-16 code units (JS `slice`), хотя `API.md` и макет говорят про 250. [проверено] | Лимит в клиенте 200 по `utf16`, обрезка по границе графемы, счётчик `N/200`. После 201 сверяем возвращённые инструкции с отправленными (`alteredStopIDs`). |
| S15 | `POST /v1/routes` не идемпотентен: каждый вызов создаёт новый маршрут. [проверено] | Конечный автомат отправки с защитой от двойного тапа, автоповторов у POST нет. Неоднозначные исходы — отдельный тип ошибки с подтверждением перед повтором (§9). |
| S16 | `packages` приводится через `Number(x) \|\| 1`, `packages_max` не проверяется. | Клиент держит значение в диапазоне `1...max` и отправляет `Int`. |
| S17 | Повторяющиеся и неизвестные `stop_id` принимаются, пробельная инструкция считается непустой. | Выбор уникален по `id`, валидация после trim. |
| S18 | notify: при HTTP 200 в теле может прийти `status: "failed"`. Ответ кешируется по `Idempotency-Key`, включая ошибку. Без ключа каждый вызов увеличивает `deliveries`. [проверено] | Контракт notify — §5.6. |
| S19 | Лимит 30 запросов в минуту на IP, фиксированное окно, `Retry-After` до 60 с. Ответы 429 тоже расходуют лимит. [проверено] | Бюджет запросов: каталог — 1 запрос, поиск с debounce, фото только лениво. На 429 показываем «retry in N s». |
| S20 | Хаос детерминирован по общему счётчику запросов сервера. | Перед записью видео сервер перезапускаем (README). |

**Направление зависимостей:** `App → RouteCore → RouteAPI`. Обратных связей нет. `RouteCore` не импортирует SwiftUI и UIKit. Сторы — это `ObservableObject` из Combine, поэтому они собираются и тестируются на macOS.

Добавить третий экран — значит добавить стор в `RouteCore`, вью в `Features/` и при необходимости метод в `RouteAPI`. Существующие модули при этом не меняются.

### 4.2 Конкурентность и язык

- Swift language mode **5** для пакета и для приложения.
- **Приложение:**
  - `SWIFT_DEFAULT_ACTOR_ISOLATION = nonisolated` вместо шаблонного `MainActor`;
  - `SWIFT_APPROACHABLE_CONCURRENCY = NO`, чтобы код вёл себя в приложении так же, как в пакете. В пакете нет ни изоляции по умолчанию, ни upcoming-флагов.
- Пакет: изоляция по умолчанию отсутствует, это поведение tools 5.9.
- **Сторы помечены `@MainActor` явно.** Вью SwiftUI работают на main actor за счёт протокола `View`.
- DTO, доменные модели, `APIError` и результаты запросов — `Sendable`.
- Протокол `Sleeper` (`func sleep(for seconds: Double) async throws`) инжектируется во всё, что ждёт: debounce и `Retry-After`. В тестах используется `ImmediateSleeper` или управляемый тестовый вариант.

**Первая задача плана** — выставить эти настройки и проверить их сборкой через `xcodebuild`.

### 4.3 Сборка зависимостей

`AppEnvironment` (app):
1. читает `APIBaseURL` из `Info.plist`;
2. создаёт `URLSessionTransport`, `APIClient` и сторы;
3. если ключа нет или URL невалиден, показывает экран «API base URL is not configured» вместо падения.

## 5. RouteAPI

### 5.1 Транспорт и запросы

- `protocol HTTPTransport: Sendable { func send(_ request: URLRequest) async throws -> (Data, HTTPURLResponse) }`.
  - Продакшен-реализация — `URLSessionTransport`.
  - В тестах — `FakeTransport`, который записывает все запросы и отдаёт заданные ответы.
- URL собирается через `URLComponents` от base URL. В `q` после стандартного кодирования `+` заменяется на `%2B`.
- Таймауты запросов: GET — 10 с, `POST /v1/routes` — 30 с, notify — 15 с, фото — 15 с.
- `POST /v1/routes` отправляет тело `{"stops":[{"stop_id":String,"packages":Int,"instructions":String}]}` с заголовком `Content-Type: application/json`.
- Наружу модуль отдаёт протоколы `StopsAPI` (`fetchAllStops()`, `searchStops(q:)`) и `RoutesAPI` (`createRoute(_:)`, `notify(...)`). Реализует их `APIClient`.

### 5.2 DTO и декодирование

**`StopDTO`**

| Поле | Тип | Если поле отсутствует или невалидно |
|---|---|---|
| `id`, `name` | `String`, обязательные и непустые | запись пропускается |
| `address`, `phone` | `String` | `""` |
| `packages_max` | `FlexibleInt?` | `Int`, строка с `Int`; ≤0 и мусор → `nil` |
| `last_delivery_at` | `FlexibleDate?` | ISO 8601 с долями секунды и без, с `Z` и без (без `Z` → UTC), число → epoch в секундах; иначе `nil` |
| `zone`, `notes` | `String?` | `nil` |

**`StopsPageDTO`**
- `items` декодируется через `LossyArray<StopDTO>?`; `null` и отсутствие поля дают `[]`.
- Наружу отдаются `skippedCount` (число пропущенных элементов) и `page` (опционально).
- `total`, `total_pages` и `has_more` не декодируются.

**`CreateRouteResponseDTO`:** `id: String` обязательно; `stops: [{stop_id, packages, instructions}]?` и `status: String?` опциональны.

**`NotifyResponseDTO`:** `stop_id`, `status`, `reason?`, `attempts?`, `sent_at?`, `deliveries?`.

**`ErrorBodyDTO`:** `error: String?`. Декодируется опционально, его отсутствие ничего не ломает.

### 5.3 Ошибки

```swift
enum APIError: Error, Sendable {
    case cancelled                                       // URLError(.cancelled) и CancellationError
    case notDelivered(URLError.Code)                     // соединение не установлено
    case ambiguous(URLError.Code)                        // все прочие URLError, включая timedOut, networkConnectionLost
    case http(status: Int, code: String?, retryAfter: Double?)
    case decoding
}
```

**Порядок маппинга** (сначала отмена):
1. `CancellationError` или `URLError(.cancelled)` → `.cancelled`.
2. `URLError` с кодом `notConnectedToInternet`, `cannotConnectToHost`, `cannotFindHost` или `dnsLookupFailed` → `.notDelivered`.
3. Любой другой `URLError` → `.ambiguous`. Неизвестные коды сознательно считаются неоднозначными.
4. Ответ вне 2xx → `.http`. `Retry-After` парсится как число секунд; если не распарсился, `nil`.
5. Ответ 2xx, но тело не разобралось → `.decoding`.

`.cancelled` никогда не показывается пользователю как ошибка GET. Для POST отмена означает неизвестный исход (§9.1).

**Исход создания маршрута** — `APIError.createRouteOutcome`:

| Исход | Условия | UI |
|---|---|---|
| `.notCreated` | `.notDelivered`; HTTP 500, 503, 429; прочие 5xx, кроме 502 и 504 | обычный Retry |
| `.maybeCreated` | `.ambiguous` (таймаут, `networkConnectionLost`, неизвестные коды); HTTP 502, 504; `.decoding` на 2xx (сервер ответил успехом, но `id` мы не знаем); `.cancelled` (запрос мог уйти до отмены) | Retry с подтверждением |
| `.rejected` | HTTP 400, 422 и прочие 4xx, кроме 429 | текст ошибки, без Retry |

Обоснование: 502 и 504 обычно отдаёт прокси, когда бэкенд уже мог создать маршрут. Решения опираются на семантику HTTP, а не на устройство `server.js`.

### 5.4 Политика повторов

Только для GET. Не больше **2 повторов**, то есть всего до 3 попыток:

| Ответ | Автоповтор |
|---|---|
| 500 | через 0,5 с |
| 503 | через `Retry-After`; если заголовка нет — 2 с; ждём не больше 5 с |
| 429 | только если `Retry-After` ≤ 5 с, иначе ошибка уходит в UI |
| `.notDelivered`, `.ambiguous`, `.decoding`, прочие коды | нет |

Ожидание идёт через `Sleeper` и учитывает отмену `Task`. **У POST автоповторов нет никогда.**

### 5.5 Пагинатор `StopPaginator`

- `page_size = 50`, страницы с 1, `maxPages = 10`.
- Записи накапливаются с дедупликацией по `id`; при повторе побеждает первое вхождение.
- Обход останавливается, если:
  - страница пустая;
  - на странице меньше 50 записей;
  - на странице нет ни одного нового `id`;
  - достигнут `maxPages`, тогда в результате `truncated = true`.
- Каждая страница запрашивается с политикой повторов §5.4. Если страница так и не загрузилась, весь обход возвращает ошибку. Частичный каталог не показываем, потому что он выглядел бы как полный.
- Пагинатор общий для каталога (без `q`) и для поиска (с `q`).

### 5.6 Контракт notify (задача из запаса)

- Успех определяется **только** по `status == "sent"` в теле ответа. HTTP 200 сам по себе успехом не считается. `status == "failed"` даёт исход `.failed(reason)`.
- Заголовок `Idempotency-Key` отправляется **всегда**. Ключ — UUID на каждую логическую попытку.
- **Повтор с тем же ключом безопасен**, поэтому все неоднозначные и транзиентные исходы повторяются **с тем же ключом**: `.notDelivered`, `.ambiguous`, `.cancelled`, HTTP 429, любые 5xx и `.decoding` (тело не разобралось). Если сервер уже отправил уведомление, он вернёт кеш, и дубля не будет.
- **Новый ключ — только после ответа `"failed"`**: старый ключ навсегда возвращает закешированную ошибку.
- 404, 422 и прочие 4xx, кроме 429, дают исход `.rejected` без повтора.

### 5.7 Результат `createRoute`

`CreatedRoute { id, status?, alteredStopIDs: [String] }`.

`alteredStopIDs` — остановки, у которых возвращённые `instructions` или `packages` отличаются от отправленных. Если сервер не вернул `stops`, список пуст.

## 6. RouteCore: модели и чистые правила

### 6.1 Модели

- `Stop` (`Sendable`, `Identifiable`, `Hashable` по `id`): `id`, `name`, `address`, `phone`, `packagesMax: Int?`, `lastDeliveryAt: Date?`, `zone: String?`. Маппинг из `StopDTO` живёт в `RouteCore`.
- `RouteStopDraft`: снимок `stop` на момент выбора, `packages: Int`, `instruction: String`.
- `RouteDraft`: `[RouteStopDraft]` в **порядке выбора**, это и есть порядок маршрута. Перезагрузка каталога черновик не меняет.

### 6.2 Правила (чистые функции с тестами)

**Сортировка:** `localizedStandardCompare` по имени.

**Секция:** первая буква имени после снятия диакритики, верхним регистром, если это A–Z. Иначе — `#`, эта секция идёт последней. Артикли не пропускаются: «The Little Zoo» попадает в T.

**Инициалы.** Имя делится по пробелам. Берутся слова, которые начинаются с буквы или цифры, кроме слова `The`. Из первых двух таких слов берутся первые символы верхним регистром. Если подходящее слово одно — один символ. Если ни одного — первый символ имени.

| Имя | Инициалы |
|---|---|
| Sova Studio Gallery | SS (в макете SG, расхождение пишем в DECISIONS) |
| Pilates 9 Studio | P9 |
| The Little Zoo | LZ |
| Zen Nails ✨ | ZN |
| Taylor & Sons Distribution | TS |
| 24/7 Pharmacy | 2P |

**Фон аватара:** индекс `(сумма unicode-скаляров id) % 5` в палитру из 5 пастелей (§10). Стабилен между запусками. `hashValue` для этого не годится, потому что меняется от запуска к запуску.

**Лимит инструкции** `InstructionRules.limit = 200` (в UTF-16 code units):
- `clamp(_:)` берёт графемы по одной, пока суммарный `utf16.count` не превысит 200. Эмодзи пополам не режется.
- `count(_:)` возвращает `utf16.count`.
- `isBlank(_:)` возвращает true, если после `trimmingCharacters(in: .whitespacesAndNewlines)` строка пуста.
- При отправке инструкции обрезаются от пробелов по краям.

**Количество:**
- `range(for stop)` — `1...max`, где `max = packagesMax ?? 99`;
- `showsMaxCaption = packagesMax != nil`;
- новое значение всегда приводится к диапазону.

**Локальный поиск** `LocalSearch.match(stop, q)`:
- `name` или `address` содержат `q` без учёта регистра и диакритики;
- **или** в `q` ≥3 цифр, и цифры телефона содержат цифры `q`.

**Подсветка:** диапазон первого вхождения `q` в имени без учёта регистра.

**Фокус ленты** `FeedFocus.layout(distances:cardHeight:activeIndex:)`. На входе — расстояние центра каждой карточки от центра видимой области (в pt), высота карточки и индекс карточки с активным полем (или `nil`). На выходе — `focusedIndex` и для каждой карточки `scaleX`, `scaleY`, `opacity`.
- `t = min(|d| / cardHeight, 1)`; `scaleX = 1 − 0.2·t`, `scaleY = 1 − 0.06·t`, `opacity = 1 − 0.35·t`.
- Если `activeIndex != nil`, эта карточка **всегда** в фокусе и для неё `t = 0`. Остальные карточки считаются по геометрии.
- Если `activeIndex == nil`, в фокусе карточка с минимальным `|d|`.

### 6.3 Сторы (`@MainActor`, `ObservableObject`)

**`RouteDraftStore`** — единственный владелец `RouteDraft`. Его разделяют пикер и лента, поэтому при навигации назад ничего не теряется.

- `select(stop, mode)`:
  - в режиме Multi добавляет остановку в конец;
  - в режиме One заменяет текущую. Замена идёт через `remove`, поэтому действует правило подтверждения.
- `remove(id) -> RemovalResult`:
  - если инструкция непустая, возвращает `.needsConfirmation(name)`;
  - `confirmRemove(id)` удаляет без вопросов;
  - если удалена последняя остановка, результат сигнализирует `.becameEmpty`.
- `switchMode(to:)`: при переходе Multi → One остаётся последняя выбранная. Если у удаляемых есть непустые инструкции, нужно подтверждение.
- `setPackages(id, n)` приводит значение к диапазону.
- `setInstruction(id, text)` применяет `clamp`. `clearInstruction(id)` очищает поле.
- `validate() -> [id]` возвращает пустые после trim; эти карточки получают флаг ошибки. Флаг снимается, как только инструкция перестаёт быть пустой.
- `totals`: число посылок и число остановок.
- `reset()`.

**`PickerStore`:**
- **Каталог:** состояние `loading`, `loaded([Stop])` или `failed(APIError)`. Есть `load()` и `reload()` (pull-to-refresh).
- **Поиск:** `query` (`@Published`) и `searchState` — `idle`, `searching`, `results([Stop])`, `empty` или `failed(APIError)`. Правила — §7.4.
- Режим выбора хранится здесь. Изменения выбора делегируются в `RouteDraftStore`.
- `reset()` очищает поиск и возвращает режим One stop.

**`SubmissionStore`** — §9.

## 7. Экран Stops

### 7.1 Структура (сверху вниз)

1. **`RouteHeader`.** Бирюзовая иконка 44 pt и статичное название «Morning route — Central area». Подзаголовок `{P} packages | {N} stops` считается по выбору; единственное и множественное число согласуются.
2. **`StepTabs`.** Stops активна, Instructions — индикатор шага: без выбора неактивна, с выбором работает как Continue.
3. **`ModeToggle`.** One stop (по умолчанию) и Multi-stop route с бейджем «New».
4. **`SearchField`** с placeholder «Search by name, street, or phone» и лупой.
5. **Список:** `ScrollView` с `LazyVStack(pinnedViews: .sectionHeaders)`, внутри `SectionHeader` и `StopRow`.
6. **`AlphabetIndex`** слева.
7. **`SelectionBar`:** чипы и `PrimaryButton`.

Системная навигационная панель на пикере скрыта.

### 7.2 Строка

- Чекбокс 23 pt, аватар 40 pt, имя и адрес с многоточием.
- Справа телефон, а у выбранной строки вместо него пилюля `N×`. Фон выбранной строки — `rowSelected`.
- Тап по строке переключает выбор.
- Пилюля — отдельная зона нажатия, **не меньше 44×44 pt** через `contentShape`, визуально как в макете. Тап открывает окно количества.

### 7.3 Каталог

- При первом показе вызывается `load()`.
- Пока идёт загрузка, показывается индикатор.
- При ошибке — текст по типу ошибки (§9.3) и Retry.
- Pull-to-refresh вызывает `reload()`.

### 7.4 Поиск

1. Debounce 350 мс через `Sleeper`. Каждый новый ввод отменяет предыдущую задачу.
2. Пустой запрос после trim показывает каталог без обращения к сети.
3. Иначе `searchStops(q как набран)` через пагинатор. Ответ применяется, только если `q` всё ещё текущий. `.cancelled` игнорируется.
4. Успех с непустым результатом → `results`.
5. Успех с пустым результатом → `LocalSearch` по загруженному каталогу. Если что-то нашлось → `results`, иначе `empty`. Если каталог не загружен, сразу `empty`.
6. Ошибка API → `failed` с Retry. Локальный поиск в этом случае **не** подменяет ошибку.

- Результаты показываются плоским списком без секций, отсортированным по §6.2. Совпадение в имени подсвечено `highlight`.
- Пустое состояние: «No stop found» и «Try another name, street, or phone».
- Пока идёт поиск, индекс A–Z скрыт. Выбор при поиске сохраняется, чипы остаются.

### 7.5 Окно количества

**Ядро:**
- полноэкранное затемнение `scrim` и карточка «Number of packages»;
- кнопки − и + по 44 pt, число по центру, кнопка Save;
- − неактивна на 1, + неактивна на максимуме;
- подпись «Max N» показывается **только** если `packagesMax` пришёл с сервера;
- Save применяет значение, тап мимо карточки закрывает окно без изменений.

Окно — свой оверлей, а не `.popover`: на iPhone под iOS 16 `.popover` открывается как sheet.

**Полировка (отдельная задача):** строка поднимается над затемнением, а у карточки появляется стрелка-указатель на пилюлю, как на экране 3 макета.

### 7.6 Чипы и Continue

- Чипы в горизонтальном `ScrollView` в порядке выбора: имя с многоточием (до 108 pt), `N×` и ✕.
- Зона нажатия ✕ — **не меньше 44×44 pt**. ✕ вызывает `remove`, при необходимости с подтверждением.
- Кнопка `Continue (1 stop)` / `Continue (N stops)`: при 0 неактивна (`disabledFill`), иначе пушит Instructions.

### 7.7 Алфавитный индекс

- Колонка A–Z слева, **28 pt шириной**, на строки не заходит: чекбокс в макете начинается на 30 pt.
- Буква выбирается тапом и протяжкой по всей высоте колонки; скролл к секции через `ScrollViewReader`.
- Буква без своей секции ведёт к ближайшей следующей.
- Колонка — единственное исключение из правила 44 pt: 26 букв по 44 pt по высоте не помещаются. Пишем в DECISIONS.

Кнопка «Remove from route» и ✕ на чипе вызывают `remove(id)`.

- Пустая удаляется сразу.
- Если остановок не осталось (`.becameEmpty`), стек очищается и открывается пикер.

**Свайп (отдельная задача):**
- карточка тянется вправо, открывая слева подложку `removeBG` с текстом «Remove from route»;
- если отпустить дальше 150 pt, срабатывает `remove`, иначе карточка пружиной возвращается;

- критерий и лимит времени — §2.

### 8.6 Фото (задача из запаса)

- `GET /v1/stops/{id}/photos` запрашивается **только для фокусной карточки**, с кешем по `stop.id` на время сессии.

- Теги: `entrance` → Entrance, `parking` → Parking, `back_door` → Back door, неизвестный тег → тег как есть.
- Изображения грузятся через `AsyncImage`; нужен интернет, они лежат на picsum.photos.

## 9. Отправка и Success

### 9.1 `SubmissionStore`

Состояния: `idle`, `submitting`, `failed(SubmissionFailure)` и `succeeded(CreatedRoute)`.

**`submit(draft)`:**
1. В состоянии `submitting` или `succeeded` ничего не делает. Это защита от двойного тапа, она срабатывает раньше, чем SwiftUI выключит кнопку.
2. Вызывает `validate()`. Если есть пустые инструкции, запрос не отправляется: лента скроллится к первой такой карточке и ставит фокус в её поле.
3. Фиксирует данные запроса: остановки в порядке черновика, `packages: Int`, инструкции после trim.
4. Переходит в `submitting` и вызывает `createRoute` в задаче, которой владеет сам стор (§9.1.1).
5. Успех → `succeeded`. Ошибка → `failed(SubmissionFailure)` по `createRouteOutcome`. **Отмена в состоянии `submitting` → `failed(.maybeCreated)`, а не `idle`**: запрос мог уйти, и сервер мог создать маршрут. Возврат в `idle` разрешил бы повторный Finish без предупреждения и привёл бы к дублю.

#### 9.1.1 Владение задачей отправки

- Задачей отправки владеет `SubmissionStore`: `private var submitTask: Task<Void, Never>?`. Ни вью, ни модификатор `.task`, ни `onDisappear` её не создают и не отменяют.
- Публичного метода отмены у стора нет, снаружи задачу никто не отменяет.
- Стор создаётся в `AppEnvironment` и живёт всё время работы приложения, так что уход с экрана задачу не прерывает.
- Если отмена всё же случилась (например, задача отменена системой), применяется правило шага 5.

`SubmissionFailure` бывает трёх видов: `.notCreated(APIError)`, `.maybeCreated(APIError)` и `.rejected(code: String?)`.

`reset()` возвращает в `idle`.

### 9.2 UI отправки

- **`submitting`:**
  - кнопка показывает «Sending…» со спиннером;
  - поля, Clear all и удаление заблокированы;
  - «назад» скрыт (§8.1).
- **`.notCreated`:** плашка с текстом (§9.3) и кнопкой Retry, которая снова вызывает `submit`.
- **`.maybeCreated`:** плашка «The route may have been created. Sending again could create a duplicate.» Retry открывает `confirmationDialog` с кнопкой «Send again», и только после неё вызывается `submit`.
- **`.rejected`:** плашка «The server rejected the route ({code}).» без Retry. Кнопка Finish остаётся доступной: если пользователь что-то изменит, он может отправить снова.

Во всех случаях с ошибкой набранное сохраняется.

### 9.3 Тексты ошибок (общие для каталога, поиска и отправки)

| Ошибка | Текст |
|---|---|
| `.notDelivered` | Can't reach the server. Check Wi‑Fi and Local Network access. |
| `.ambiguous` (GET) | The server didn't respond in time. |
| HTTP 429 | Too many requests. Try again in {N} s. (если `Retry-After` нет — «Try again in a minute.») |
| HTTP 5xx | The server had a problem (HTTP {status}). |
| прочие HTTP 4xx на GET | Request failed (HTTP {status}). |
| `.decoding` | Unexpected response from the server. |

### 9.4 Success

Экран пушится как `.success(CreatedRoute)`, без «назад» (`navigationBarBackButtonHidden(true)`).

На экране:
- «Route {id} created»;
- `{N} stops · {P} packages`;
- предупреждение, если `alteredStopIDs` не пуст: «The server changed instructions for {k} stops.»;
- кнопка **New route**. Она вызывает `RouteDraftStore.reset()`, `SubmissionStore.reset()` и `PickerStore.reset()`, затем `path = []`. Каталог не перезагружается.

Вернуться к отправленному маршруту нельзя никаким путём.

**Notify (задача из запаса).** На Success для каждой остановки виден статус: sending, sent или failed с Retry. Уведомления отправляются последовательно по одному, по контракту §5.6. Повтор после `failed` идёт с новым ключом. Сноска на карточке снова упоминает водителя.

## 11. Конфигурация

- `RouteBuilder/Config/App.xcconfig`:
  ```
  // Mac's LAN IP; see README. "//" starts a comment in xcconfig, hence $()
  API_BASE_URL = http:/$()/10.204.20.147:4000
  ```
- `RouteBuilder/Config/Info.plist`:
  - `APIBaseURL = $(API_BASE_URL)`;
  - `NSAppTransportSecurity` → `NSAllowsLocalNetworking = YES`;
  - `NSLocalNetworkUsageDescription` = «Route Builder connects to the dispatch server on your local network.».
- Build settings таргета:
  - `INFOPLIST_FILE = Config/Info.plist`;
  - `GENERATE_INFOPLIST_FILE` остаётся `YES`, Xcode склеит наш файл со сгенерированными ключами.
- `Config/` лежит **вне** синхронизируемой папки `RouteBuilder/RouteBuilder/`. Иначе `Info.plist` попадёт в ресурсы и сборка упадёт с ошибкой «Multiple commands produce Info.plist».
- **Ручные шаги автора в Xcode** (отдельными пунктами плана):
  1. Подключить `App.xcconfig` как base configuration таргета для Debug и Release (Project → Info → Configurations).
  2. Подключить локальный пакет `RouteBuilderKit` (Add Package Dependencies → Add Local…) и добавить в таргет **обе** библиотеки: `RouteAPI` и `RouteCore`.

  После каждого шага агент проверяет сборку через `xcodebuild`.
- **Риск ATS.** Если на устройстве `NSAllowsLocalNetworking` не разрешает HTTP на голый IP, запасной вариант — `NSAllowsArbitraryLoads` только в Debug-конфигурации. Решение пишем в DECISIONS.

- Сборка URL: `+`, `&` и пробел в `q`, `page_size=50`.
- Классификация в `APIError`:
  - каждый перечисленный код `URLError`, включая `.cancelled` → `.cancelled`;
  - `CancellationError`;
  - неизвестный код → `.ambiguous`.
- `createRouteOutcome` — таблица: `.notDelivered`, `.ambiguous`, `.decoding` и HTTP 400, 404, 422, 429, 500, 502, 503, 504.
- Повторы:
  - 500 → повтор;
  - 503 → повтор после `Retry-After`;
  - 429 с коротким и с длинным `Retry-After`;
  - лимит в 2 повтора;
  - POST на 500, 503 и таймаут отправляет ровно 1 запрос.
- Пагинатор:
  - сдвинутая страница с дублем;
  - пустая страница с ложным признаком «есть ещё»;
  - страница без новых `id`;
  - `maxPages` и `truncated`;
  - ошибка на второй странице → ошибка всего обхода.
- `alteredStopIDs`.
- Notify (вместе с задачей из запаса):
  - `"failed"` при HTTP 200;
  - тот же ключ после таймаута, `.notDelivered`, 429, 5xx и неразобранного тела;
  - новый ключ только после `"failed"`;
  - 404 и 422 → `.rejected` без повтора.

**RouteCoreTests**
- Правила: инициалы (таблица §6.2), секции и `#`, сортировка, индекс аватара, `clamp` по графемам (эмодзи на границе 200), `isBlank`, диапазон количества и `showsMaxCaption`, `LocalSearch` (регистр, диакритика, цифры телефона), диапазон подсветки.
- `FeedFocus.layout`:
  - без активного поля в фокусе ближайшая к центру карточка;
  - с активным полем в фокусе она, `t = 0`, даже если ближе к центру другая;
  - проверка значений `scale` и `opacity`.
- `PickerStore`:
  - debounce: серия вводов даёт один запрос;
  - устаревший ответ отбрасывается;
  - отмена не приводит к `failed`;
  - пустой успешный ответ дополняется локальным поиском;
  - ошибка API даёт `failed` без локальной подмены;
  - пустой запрос не уходит в сеть.
- `RouteDraftStore`:
  - замена в режиме One;
  - переход Multi → One;
  - `remove` → `.needsConfirmation` при непустой инструкции и `.becameEmpty`;
  - `validate` и снятие флага ошибки;
  - `totals`.
- `SubmissionStore`:
  - двойной `submit` → 1 POST;
  - невалидный черновик → 0 POST;
  - соответствие исходов `.notCreated`, `.maybeCreated`, `.rejected`;
  - отмена во время `submitting` → `failed(.maybeCreated)`, не `idle`; следующий `submit` возможен только как повтор из `failed`;
  - повтор после ошибки;
  - `succeeded` блокирует новый `submit`;
  - `reset`.

**RouteAPILiveTests** (opt-in). Запускаются, только если задан `ROUTE_API_LIVE_URL`, иначе `XCTSkip`. Прогоняют пагинатор и поиск против настоящего `server.js`:
- в каталоге нет дублей по `id`;
- обход завершается;
- `q=sov` даёт пустой результат, а `q=Sov` находит запись.

Пример запуска: `ROUTE_API_LIVE_URL=http://localhost:4000 swift test --filter RouteAPILiveTests`. Каждый прогон тратит часть лимита в 30 запросов в минуту.

**Сборка приложения:** `xcodebuild -scheme RouteBuilder -destination 'generic/platform=iOS Simulator' build` после задач, которые трогают приложение.

**Ручная проверка на устройстве:** чек-лист в `docs/ai/verification.md`:
- полный поток из видео;
- авиарежим при загрузке и при отправке;
- быстрый поиск до 429;
- двойной тап по Finish;
- удаление последней остановки;
- отказ и затем разрешение Local Network;
- эмодзи на границе 200;
- поиск строчными буквами (`sov`).

UI-тестов нет, это пишем в DECISIONS.

## 14. Порядок реализации (ограничения для плана)

1. Настройки конкурентности и языка (§4.2) с проверкой сборкой.

4. Конфигурация (§11): `App.xcconfig`, `Info.plist`, `AppEnvironment`. *Ручной шаг автора:* подключить xcconfig. Затем проверка на iPhone: `GET /health` из приложения проходит, ATS не мешает.
5. `RouteAPI` в порядке TDD: DTO → ошибки → повторы → пагинатор → `createRoute`.
6. Правила и сторы `RouteCore` в порядке TDD.
7. Тема и компоненты.
8. Экран Stops.
9. Экран Instructions.
10. Отправка и Success.
11. README, DECISIONS, AI_PROCESS, verification. Ревью ядра.

    1. полировка окна количества;

    3. notify;
    4. фото.

    Каждая — отдельная задача. Ни одна задача ядра от них не зависит.

## 15. Риски

| Риск | Что делаем |
|---|---|
| `NSAllowsLocalNetworking` не разрешает HTTP на голый IP | Проверка на шаге 4. Запасной вариант — `NSAllowsArbitraryLoads` только в Debug. |
| `DragGesture` свайпа конфликтует со скроллом `ScrollView` | Свайп — отдельная задача с лимитом в 1 час. Кнопка удаления есть в ядре. |
| Фокус-эффект через `GeometryReader` тормозит на ленте | Карточек немного (это остановки одного маршрута). Расчёт — чистая функция, вью только применяет результат. |
| Лимит 30 запросов в минуту при демо | Каталог — 1 запрос, поиск с debounce, фото только лениво, перед видео сервер перезапускается. |
| IP Mac сменится (DHCP) | IP задан в одном месте, в README описано, как его узнать. |
